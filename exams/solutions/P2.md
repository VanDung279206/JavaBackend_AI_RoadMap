# Đối chiếu Phase 2

Schema cần primary key, khóa ngoại `invoices.user_id → users.id`, NOT NULL, CHECK(amount>=0). Dùng `numeric` với precision/scale phù hợp nếu amount là tiền thực; fixture chỉ dùng số nguyên đơn vị quy ước.

```sql
SELECT u.id, u.name, COUNT(i.id) AS invoice_count,
       COALESCE(SUM(i.amount),0) AS total_amount
FROM users u LEFT JOIN invoices i ON i.user_id=u.id
GROUP BY u.id,u.name ORDER BY u.id;
```

Kết quả: `(10,Lan,2,300)`, `(20,Minh,1,50)`, `(30,Vy,0,0)`.

```sql
SELECT id,amount FROM invoices WHERE user_id=10 ORDER BY id DESC LIMIT 1;
SELECT id,amount FROM invoices WHERE user_id=10 AND id<502 ORDER BY id DESC LIMIT 1;
```

Trang đầu 502, trang sau 501. Index tham khảo `(user_id,id DESC)`; phải đo trên dữ liệu đủ phù hợp mới kết luận hiệu năng.

```sql
BEGIN;
INSERT INTO invoices(id,user_id,amount) VALUES(503,10,80);
INSERT INTO audit(invoice_id,action) VALUES(503,'CREATED');
ROLLBACK;
SELECT COUNT(*) FROM invoices WHERE id=503;
SELECT COUNT(*) FROM audit WHERE invoice_id=503;
```

Hai count phải là 0. API dùng principal → user_id. POST hợp lệ 201; amount âm 400; chưa xác thực 401; đọc ID của user khác theo hợp đồng 404. Ghi rõ trạng thái trên là **kỳ vọng**, chỉ đánh dấu đã chạy sau khi kiểm tra trên PostgreSQL.
