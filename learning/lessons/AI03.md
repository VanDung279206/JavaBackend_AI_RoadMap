# AI03 — Timeout và retry hữu hạn

## Mục tiêu và kiến thức trước

Đặt deadline, phân loại lỗi tạm thời và chặn retry vô hạn.

**Cần biết trước:** AI01; exception và executor.

## Tình huống

Gateway đôi khi timeout. Retry mọi lỗi có thể lặp mãi hoặc lặp thao tác có side effect.

## Ví dụ chạy được

Lệnh từ gốc repository: `java learning/examples/AI03.java`. Java cần JDK 17+; ví dụ Python dùng thư viện chuẩn.

```java
import java.util.*;
import java.nio.file.*;
import java.util.concurrent.*;

public class AI03 {
    public static void main(String[] args) throws Exception {
        var pool=Executors.newSingleThreadExecutor();
        var gate=new CountDownLatch(1);
        try {
            Future<String> task=pool.submit(()->{ gate.await(); return "ok"; });
            try { task.get(20,TimeUnit.MILLISECONDS); } catch(TimeoutException e) { task.cancel(true); System.out.println("timeout cancelled"); }
            int attempts=0;
            while(attempts<3) { attempts++; if(attempts==3) break; }
            System.out.println("attempts="+attempts);
        } finally { gate.countDown(); pool.shutdownNow(); }
    }
}
```

**Diễn giải từng bước:**

1. Task chờ latch nên chắc chắn chưa hoàn tất; get có deadline.
2. Timeout gọi cancel(true), task phải hợp tác với interrupt; network client thật cũng cần timeout.
3. Loop minh họa budget tổng ba lần (gồm lần đầu); P5.4 chỉ retry lỗi tạm thời, có backoff/jitter và deadline chung.

**Kết quả:**

```text
timeout cancelled
attempts=3
```

## Lỗi thường gặp

**Nhận biết:** Retry validation/401 hoặc chờ vô hạn; retry mỗi tầng làm số lần nhân lên.

**Cách sửa:** Phân loại retryable, giới hạn attempt/deadline; dùng idempotency khi thao tác có side effect và đo số lần gọi fake.
